# 블로그·이력 로그 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**목표:** 기존 정적 포트폴리오에 Jekyll 기반 `/blog/`(기술 글)와 `/log/`(이력 로그)를 추가한다. 프로젝트 페이지에는 관련 글을 연결한다.

**구조:** GitHub Pages 내장 Jekyll이 빌드한다. 기존 HTML은 front matter가 없으므로 그대로 복사된다. 기술 글은 `_posts/`, 로그는 `_log/` 컬렉션에 둔다. 레이아웃은 `projects/project.css`를 그대로 링크하고, Markdown 본문용 스타일만 `assets/blog.css`에 추가한다.

**기술 스택:** Jekyll 3.x (`github-pages` gem), Liquid, `jekyll-feed`, `jekyll-sitemap`, `jekyll-seo-tag`, 검증용 Python 3 표준 라이브러리.

**설계 문서:** `docs/superpowers/specs/2026-11-25-blog-design.md`

## 공통 제약

- `index.html`, `resume.html`에는 front matter를 넣지 않는다. 빌드 결과가 원본과 바이트 단위로 같아야 한다.
- `projects/*.html`은 맨 앞의 빈 front matter와 `</body>` 바로 앞의 include 한 줄 외에는 수정하지 않는다.
- 플러그인은 `jekyll-feed`, `jekyll-sitemap`, `jekyll-seo-tag`만 쓴다 (GitHub Pages 허용 목록).
- 퍼머링크: 전역은 `/blog/:title/`, `_log` 컬렉션은 `/log/:title/`.
- `project` 값은 다음 중 하나만 쓴다: `ehr`, `eland-folder-mall`, `foodcare-cle`, `group-ai-platform`, `hl-science-mall`, `investment-review-agent`, `smilegate-global`, `wegive`
- EN 모드에서 본문 위에 띄우는 안내 문구는 정확히 `This post is written in Korean.`로 한다.
- 언어 토글은 기존 방식(`localStorage` 키 `lang`, `html[data-lang]`, `[lang="ko|en"]` 요소 숨김)을 그대로 따른다.
- 글 파일명은 `YYYY-MM-DD-영문소문자-숫자-하이픈.md` 형식으로 한다.
- `timezone: Asia/Seoul`로 설정한다. 설정하지 않으면 오늘 날짜로 쓴 글이 UTC 기준으로 "미래 글"이 되어 빌드에서 빠질 수 있다.

## 리뷰 중점 항목

1. **`project` 오타**: 관련 글이 아무 경고 없이 사라지면 안 된다. 허용 목록 밖의 값이면 검증 스크립트가 실패해야 한다. (Task 4)
2. **`title_en`이나 `summary_en`이 없는 기술 글**: EN 모드에서 빈 칸이 아니라 한국어 제목이 보여야 한다. (Task 2)
3. **한글 파일명**: 인코딩된 URL이 생기면 안 된다. 파일명 규칙 위반은 검증 스크립트가 실패해야 한다. (Task 1)
4. **기존 페이지 무손상**: `index.html`과 `resume.html`의 빌드 결과가 원본과 같아야 한다. 이력서 원본이 있는 `files/`는 배포되면 안 된다. (Task 1)
5. **페이지 간 언어 유지**: 포트폴리오에서 EN을 고르고 블로그로 이동해도 EN이 유지되어야 한다. (Task 2)
