Background

HL사이언스의 건강기능식품을 파는 자사 쇼핑몰입니다. 자사몰 주문과 네이버페이 주문이 함께 들어옵니다.

The direct store of HL Science, which sells health supplements. Orders arrive both from the store itself and through Naver Pay.

Problem

네이버페이로 들어온 주문을 운영자가 따로 확인해야 했고, 관리자 화면의 주문 검색은 조건이 부족했습니다.

Operators had to check Naver Pay orders separately, and order search in the admin screens lacked conditions.

What I did

월 2,000건 이상 주문 무장애 운영Over 2,000 orders a month without an outage
월 2,000건이 넘는 주문을 장애 없이 운영했습니다.I ran a store with over 2,000 orders a month without an outage.
네이버페이 주문형 API 연동Naver Pay order API
네이버페이 주문을 쇼핑몰 주문으로 받아 오도록 연동했습니다.I integrated the API so Naver Pay orders arrive as store orders.
주문 중복 방지No duplicate orders
네이버페이 주문 번호를 기준으로 이미 받은 주문은 다시 만들지 않게 했습니다. 수집이 실패하면 다음 주기에 이어서 받습니다.Orders already received are skipped using the Naver Pay order number. If a collection run fails, the next run picks up where it stopped.
관리자 검색 고도화Better admin search
주문 번호, 주문자, 상품, 기간, 결제 수단을 조합해 찾을 수 있게 하고, 자주 쓰는 조건에 맞춰 인덱스를 정리했습니다.Admins can combine order number, buyer, product, period and payment method, and I tuned indexes for the conditions used most.

Hard parts

  • 외부 주문은 취소와 반품 상태가 뒤늦게 바뀌어 들어옵니다. 상태 동기화를 주기적으로 다시 돌려 맞췄습니다.Outside orders change to cancelled or returned after the fact. Re-running the status sync on a schedule keeps them aligned.

Result

월 2,000건 이상의 주문을 장애 없이 처리했습니다.

Over 2,000 orders a month were handled without an outage.

What I learned

  • 외부 주문을 내부 주문과 같은 형태로 바꿔 두면, 그 뒤의 운영 화면은 고칠 것이 거의 없습니다.Once outside orders are converted into the same shape as internal ones, the operations screens behind them barely need changing.
