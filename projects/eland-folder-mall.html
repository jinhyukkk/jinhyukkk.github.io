ELAND FOLDER MALL 구축과 운영ELAND FOLDER MALL build and operations

포비즈코리아Forbiz Korea

하루 평균 1,000건 이상의 주문을 다루는 슈즈 커머스에서, Best 상품 집계를 조회 경로에서 떼어 내 조회를 10초에서 1초 이내로 줄였습니다. 개발자 3명 중 한 명으로 구축부터 운영까지 맡았습니다.

On a shoe store handling over 1,000 orders a day, I moved best-seller aggregation off the read path and cut listing from 10 seconds to under 1. I was one of 3 developers, from build through operations.

Service

이랜드의 오프라인 슈즈 편집숍 폴더(FOLDER)의 공식 온라인 스토어입니다. 아디다스, 아식스, 컨버스, 크록스, 호카 등 여러 브랜드의 신발과 단독 상품을 팝니다. 브랜드, 신상품, 랭킹, 세일, 프로모션, 이벤트 메뉴로 구성되며, 일반 쇼핑몰에 팔로우와 게시판 같은 커뮤니티 기능을 더했습니다. 제가 개발하고 운영한 서비스는 종료됐고, 지금은 새로 만든 사이트가 운영되고 있습니다.

The official online store of FOLDER, E-Land's offline multi-brand shoe shop. It sells shoes from brands such as Adidas, Asics, Converse, Crocs and Hoka, along with exclusives. The store is organized into brands, new arrivals, ranking, sale, promotions and events, with community features such as follows and boards on top. The service I built and ran has since been closed, and a newly built site runs in its place.

Problem

Best 상품 화면이 열릴 때마다 주문과 조회 기록을 실시간으로 집계하는 무거운 쿼리가 돌았습니다. 데이터가 쌓일수록 응답 시간이 늘어 조회에 10초가 걸렸고, 운영팀에서 계속 문제로 올라왔습니다. EXPLAIN으로 보니 풀 스캔과 임시 테이블이 생기고 있었고, 집계에 쓰는 컬럼 일부에는 인덱스가 없었습니다.

Every time the best-seller page opened, a heavy query aggregated order and view logs live. Response time grew with the data until listing took 10 seconds, and the operations team kept raising it. EXPLAIN showed full scans and temporary tables, and some aggregated columns had no index.

What I did

Best 상품 조회 10초 → 1초 이내Best-seller listing, 10 s → under 1 s
Best 상품을 미리 집계해 별도 테이블에 쌓는 배치를 만들고, 화면은 그 테이블만 읽게 했습니다. 사용자 요청이 무거운 집계를 떠안지 않도록 읽기와 집계 경로를 나눈 것입니다. 집계 쿼리에 빠진 인덱스도 보강해 배치 자체도 빨라졌습니다. EXPLAIN에서는 주문 상세 테이블 풀스캔에 GROUP BY가 겹쳐 Using temporary; Using filesort가 나왔습니다. 배치는 1시간마다 Cron으로 돌리고, 결과를 새 테이블에 쌓은 뒤 RENAME TABLE로 한 번에 바꿔 배치가 실패해도 직전 순위가 남게 했습니다. 당시 인프라에 Redis가 없었고, 테이블에 두면 관리자 화면과 다른 조회에서도 조인해 쓸 수 있고 재시작해도 결과가 남아 테이블을 택했습니다.I built a batch that aggregates best sellers ahead of time into a separate table, and the page now reads only that table, so user requests no longer carry the heavy aggregation. I also added the missing indexes, which sped up the batch itself. EXPLAIN showed a full scan of the order detail table combined with GROUP BY, giving Using temporary; Using filesort. The batch runs hourly on cron, writes into a new table and swaps it in with RENAME TABLE, so a failed run leaves the previous ranking in place. There was no Redis in the stack then, and a table can be joined from the admin pages and other queries and survives restarts, so I chose a table.
Elasticsearch 검색Elasticsearch search
Elasticsearch로 상품 검색과 최근 본 상품 기록 기능을 만들고, 관리자 페이지 검색도 Elasticsearch로 고도화했습니다.I built product search and recently viewed products on Elasticsearch, and extended Elasticsearch to search in the admin pages.
커뮤니티와 프로모션 기능Community and promotion features
폴더 SNS(FolderingChannel)의 팔로우, UGC 신고와 차단, 후기·평점 관리, 게시판을 단독으로 개발했습니다. 초성퀴즈, TimeSale, 추첨·래플 같은 이벤트 기능도 메인으로 맡았습니다.I built follows, reporting and blocking for user content, review and rating management, and boards for the FOLDER social feed (FolderingChannel) on my own, and led event features such as an initial-consonant quiz, TimeSale and raffles.
외부 시스템 연동Outside systems
본인인증, 회원정보, 후기종합, 평점통계를 외부 시스템과 연동했습니다. Google, Naver, Facebook의 분석·마케팅 스크립트도 붙였습니다.I connected identity verification, member data, combined reviews and rating statistics with outside systems, and added analytics and marketing scripts from Google, Naver and Facebook.
운영 자동화Operations automation
Linux Cron으로 운영 배치를 자동화하고, Jenkins로 자동 배포와 수동 배포를 구성했습니다.I automated operations batches with Linux cron and set up automatic and manual deploys with Jenkins.
구축 6개월, 운영 1년 10개월6 months of build, 22 months of operations
2020년 12월부터 구축하고 2021년 5월부터 운영했습니다. 운영 중에 나온 버그를 바로 대응해 서비스를 안정적으로 유지했습니다.I worked on the build from December 2020 and on operations from May 2021, responding quickly to bugs to keep the service stable.

Result

Best 상품 조회를 10초에서 1초 이내로 줄였고, 사용자 요청이 집계 부하에서 분리됐습니다.

Best-seller listing went from 10 seconds to under 1, and user requests no longer carry the aggregation load.
